# TaniAfrika — AI Agent Guidelines & Engineering Standards

> **Document Purpose:** This document is the primary directive and operating manual for any AI model, assistant, or engineer working in this repository. All code generation, refactoring, and architectural modifications must comply with the rules, boundaries, and standards outlined below.

---

## 1. Project Overview & Architecture

* **Product:** **TaniAfrika** — A Kenyan, mobile-first marketplace connecting individuals and businesses with verified drivers and suitable vehicles for house moves, commercial deliveries, and parcel transport.
* **Architecture:** **Modular Monolith**
  * PostgreSQL (Supabase) is the single source of truth for state, identity, money, and access control.
  * Explicit domain separation: Identity, Fleet/Compliance, Marketplace, Dispatch/Location, Money/Escrow, Accounting Ledger, and Trust/Operations.
  * Transactional event outbox pattern for asynchronous side-effects.
* **Tech Stack:**
  * **Frontend:** Next.js 16 (App Router), React 19, TypeScript 5.
  * **Styling:** Tailwind CSS v4, CSS Theme Tokens (Reliable Neighbour palette).
  * **Backend & DB:** Supabase (PostgreSQL 15+ with PostGIS, Citext, Pgcrypto), Row-Level Security (RLS), Edge Functions (Deno/TypeScript).
  * **Maps & Geo:** Leaflet / React-Leaflet, PostGIS spatial queries.

## 3. Core Business Logic & Inviolable Rules

1. **Bid Acceptance Precondition:**
   `public.accept_bid(p_order_id, p_bid_id)` will **fail** unless:
   * Winning driver has `approval_status = 'approved'`.
   * Driver has at least one active, verified vehicle (`is_active = true` AND `is_verified = true`).
2. **Order State Machine Progression:**
   $$\text{pending} \xrightarrow{\text{accept\_bid}} \text{payment\_pending} \xrightarrow{\text{payment}} \text{assigned} \rightarrow \text{driver\_en\_route} \rightarrow \text{arrived} \rightarrow \text{loading} \rightarrow \text{picked\_up} \rightarrow \text{in\_transit} \rightarrow \text{delivered} \rightarrow \text{completed}$$
   * Driver status transitions **must** be executed via `public.update_order_status(p_order_id, p_new_status, p_notes)`.
   * Order completion (`completed`) is driven by payout posting, not by client UI updates.
3. **Staging Test Payment (Handshake W5):**
   * While `mpesa_payments` feature flag is `false`, client orders pause at `payment_pending`.
   * Advancing to `assigned` is performed **only** by an Admin clicking "Confirm test payment" on `/orders/[id]`, which invokes `public.record_payment_success` using the `service_role` client.
   * Never fake payment completion on the client.
4. **Financial Integrity & Currency:**
   * All internal monetary amounts are stored in **minor integer units** (cents) as `bigint` (e.g., `total_amount_minor`, `platform_fee_minor`, `driver_earnings_minor`).
   * Display amounts are derived by dividing minor units by 100 (`amount_minor / 100 KES`).
   * Never hardcode platform commission rates. Always read `platform_fee_minor` generated by `accept_bid`.
   * Posted ledger transactions and entries are strictly immutable.

## 5. Design System: "Reliable Neighbour"

All UI implementations on driver and admin surfaces must reflect the **Reliable Neighbour** design direction:

### Palette & Tokens
* **Brand Primary Green:** `#1F5F3F` (Deep Trust Green) / `#006044`
* **Warm Neutral / Paper Background:** `#F7F1E5` / `#FFF8F4`
* **Card & Surface Background:** `#FFFFFF`
* **Primary Ink / Typography:** `#1C1D20` / `#2A2A28` / `#33353A`
* **Accent Sage / Muted Green:** `#7A9080`
* **Accent Amber / Warning:** `#D4A244`
* **Error / Red:** `#DC2626`
* **FORBIDDEN:** Purge legacy `#ef4d16` (orange-600) and maroon (`#A32A42`) from all owned routes.

### UX & Layout Standards
* **Mobile-First:** Target 390px to 412px viewports for driver flows.
* **Component States:** Every data-driven component **must** handle:
  1. Loading skeleton/spinner.
  2. Empty state with clear messaging and actionable CTA.
  3. Error state with retry action.
* **Touch Targets:** Minimum 44x44px for all mobile interactive buttons.
* **Typography:** Base font size $\ge 14\text{px}$ for readability on mid-tier mobile screens.

## 6. Code Standards & Architecture Guidelines

1. **Next.js & React:**
   * Prefer React Server Components (RSC) for data fetching.
   * Mark client files with `'use client'` only when state, event handlers, or browser APIs are required.
   * Implement mutations using Next.js Server Actions with proper validation and authentication checks.
2. **Database & Supabase:**
   * Rely on Row-Level Security (RLS). Browser code must never possess elevated permissions.
   * Use `service_role` keys exclusively inside authenticated server actions or Edge Functions.
   * Always import types from `@/types/database.generated.ts` or `@/types/supabase.ts`.
3. **Storage:**
   * Use existing private buckets: `driver-documents`, `vehicle-documents`, `order-evidence`.
   * Respect standard bucket paths:
     * Driver documents: `{userId}/{document_type}-{timestamp}.ext`
     * Vehicle documents: `{vehicleId}/{document_type}-{timestamp}.ext`
     * Order evidence: `{orderId}/pickup_proof-{timestamp}.jpg` or `delivery_proof-{timestamp}.jpg`
4. **Defensive Programming:**
   * Validate all inputs using Zod or strict TypeScript assertions.
   * Never commit API keys, service role keys, or secrets into source files.
